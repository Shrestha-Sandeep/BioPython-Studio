# P02 — Sample labels and quality decisions

**Outcome:** build a reliable sample label, identify malformed identifiers and implement a clearly documented measurement rule. This chapter covers competencies **008–011**.

## 1. Labels must preserve identity

A microscope image is not useful without knowing which specimen and condition it belongs to. The text `"N2"`, integer `3` and text `"control"` should not be joined by guesswork. Make a label from explicitly named values.

```python
strain = "N2"
plate = 3
condition = "control"
sample_id = f"{strain}_P{plate:02d}_{condition}"
print(sample_id)
```

An f-string substitutes variable values into a human-readable string. The `:02d` format asks for an integer rendered with at least two digits, so 3 becomes `03`. Formatting affects appearance, not the type of the original `plate`.

Changing a strain label must change the resulting ID; the output should never be hardcoded. Decide on a format before collecting data, and never silently reinterpret identifiers after acquisition.

## 2. Parse before trusting

For a label such as `"N2_P03_control"`, `split("_")` returns three pieces. But what if a label is empty, includes too many separators or uses `Pxx` instead of a number? A well-behaved program must distinguish valid inputs from malformed inputs. A string method only performs an operation; it does not validate scientific meaning.

```python
label = "N2_P03_control"
parts = label.split("_")
print(parts)
```

The parser exercises use deliberately simple identifier rules: three non-empty components, a plate code beginning with `P`, and numeric plate digits. These are **course conventions**, not a universal lab data standard. Production datasets can include underscores inside terms and require a proper documented schema; later lessons handle that.

## 3. A quality-control decision is a declared policy

Suppose a fluorescence field was marked usable if its focus score is at least 0.70. Python compares numbers with `>=`, `<`, `==` and other operators; the comparison returns a Boolean.

```python
focus_score = 0.74
minimum_focus = 0.70
acceptable = focus_score >= minimum_focus
print(acceptable)
```

A conditional can then choose between actions:

```python
if focus_score >= minimum_focus:
    print("review-eligible")
else:
    print("flag-for-review")
```

**Do not mistake this training rule for a validated biological QC threshold.** A numeric score and cutoff need documented definition and empirical calibration. Automated exclusions can bias group comparisons, especially if one condition systematically fails QC. Keep the rejected records and reasons, even if a later analysis excludes them.

## 4. Predict, investigate, transfer

What happens at exactly 0.70? The operator `>=` includes that boundary, while `>` excludes it. Before coding, define the desired treatment of equality.

Compare strings only when the task requires textual equality. Do not treat `"0.74"` as the number `0.74`; converting text may fail and deserves an explicit error. Practice examples use true floats.
